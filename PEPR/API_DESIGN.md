# API Design

## Overview
The Backend exposes a stable, versioned REST API at `/api/v1/`. It relies on FastAPI for auto-generated OpenAPI documentation.

## Authentication & Authorization
- **Method**: Bearer JWT Tokens.
- **Roles**: `admin`, `researcher`, `viewer`.
- **API Keys**: System will support API Key auth for future PIDE system integrations.

## Core Endpoints

### 1. Auth & Users
- `POST /api/v1/auth/login`: Authenticate and receive JWT.
- `GET /api/v1/users/me`: Get current user details.

### 2. Dashboard & Reporting
- `GET /api/v1/reports/weekly`: Fetch generated weekly economic reports.
- `GET /api/v1/reports/{id}`: Fetch specific report details.

### 3. Economic Data
- `GET /api/v1/data/indicators`: List available economic indicators.
- `GET /api/v1/data/series`: Fetch time-series data with filtering (date ranges, sources).
- `GET /api/v1/data/anomalies`: Fetch flagged anomalies generated by the ML engine.

### 4. System & AI
- `POST /api/v1/ai/query`: Chat interface for researchers to interact with the AI Gateway. (Requires `researcher` or `admin` role).

## Standardization
- All endpoints must return a standardized JSON envelope:
  ```json
  {
    "status": "success|error",
    "data": {},
    "meta": { "pagination": {} },
    "error": null
  }
  ```
